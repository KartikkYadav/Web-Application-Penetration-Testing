# id Parameter Behavior

The URLs you provided test the `id` parameter behavior on the error-based injection page with various types of input:

- `id=1` : A normal integer ID that should return the user with ID 1 if existing.
- `id=-1` : A negative number, likely no user with this ID, may lead to no result or error.
- `id=99999999999999999999999999999999999999999999999999999999999999999999999999` : An extremely large number, probably no matching record, tests how the system handles large values.
- `id=admin` : A string instead of integer, testing type handling and potential error output or injection attempts.

Based on the PHP code, these inputs are directly inserted into the SQL query, so:

- Numeric values will be used as-is in the query.
- String inputs like `"admin"` will also be used directly, causing the query to become syntactically incorrect, which may result in a displayed SQL error message.

This is characteristic of an error-based SQL injection vulnerability where database errors help attackers learn about the database structure and behavior.

For instance:

- The string input will likely produce a SQL syntax error.
- Very large numbers might return no result or cause unexpected behavior.
- Negative numbers may return no results but should not normally produce an error.

This interaction helps attackers craft further injection payloads by examining error messages or responses.

# Explanation of SQL Injection Techniques Using id Parameter

- `%23` or `#` in the URL represent SQL comment operators.
- These comments cause the database to ignore everything after the injected payload.
- Logical operators such as `OR` manipulate the query condition.
- Payloads like `' or 1='1` force the query to evaluate as true.
- SQL comments like `--+` help avoid syntax issues caused by trailing query parts.

---

# How These Techniques Work

- The comment operator (`#` or `--`) instructs SQL to ignore everything after it.
- Logical conditions such as `' or '1'='1` alter the `WHERE` clause logic.
- These payloads exploit applications where user input is inserted directly into SQL queries without sanitization or parameterization.

---

# Run Multiple SELECT Statements in One Query Using UNION ALL

## Using UNION ALL SELECT for SQL Injection

The URLs provided demonstrate how to use the `UNION ALL SELECT` statement for SQL injection to run multiple select statements in one query via the `id` parameter.

- The `UNION ALL` operator combines the results of two or more `SELECT` queries.
- This technique lets attackers append a crafted `SELECT` statement to the original query to extract or manipulate data.
- The number of columns in the `SELECT` after `UNION ALL` must match the number of columns in the original query.

---

# Example URLs and Explanation

    http://192.168.1.31/web-pentest/error-based-string.php?id=1' union all select 1,2,3,4,5,6,7 --+

    http://192.168.1.31/web-pentest/error-based-string.php?id=-1' union all select 1,2,3,4,5,6,7 --+

    http://192.168.1.31/web-pentest/error-based-string.php?id=99999999' union all select 1,2,3,4,5,6,7 --+

    http://192.168.1.31/web-pentest/error-based-string.php?id=admin' union all select 1,2,3,4,5,6,7 --+

    http://192.168.1.31/web-pentest/error-based-string.php?id=-1' union all select 100,200,3,4,5,6,7 --+

---

# How It Works

- The `id` parameter injects a `UNION ALL SELECT` appended to the original query.
- Each number (`1,2,3...`) represents a column value in the injected result.
- The web page response reveals the injected values in columns, showing which injection succeeded.
- Adjusting numbers or values helps identify interesting columns or test data display.

---

# Important Notes

- The number of columns in `UNION ALL SELECT` must match the number found in the previous step.
- If fewer or more columns are selected than expected, SQL errors occur.
- Using comments like `--+` terminates the SQL statement cleanly and avoids syntax issues.

---

# How to Interpret

- If injection is successful, the web page displays injected values (`1,2,3...`) in the output.
- This confirms the number of columns and which columns are reflected in the response.
- Changing values helps identify useful columns for further testing.

This technique is a classic approach in error-based and union-based SQL injection to enumerate database structure and extract data by combining crafted queries with the original query.
